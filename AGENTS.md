# MicroFlow: project boundaries and working agreement

## Boundaries

- Work only inside this repository. Do not read, modify, clean up or run commands in sibling repositories
  or in the user's configuration.
- Keep dependencies, toolchains, caches, SDKs, browser binaries and temporary files inside the repository.
  Python packages live in `.venv/`, installed with `uv`.
- Never install software globally. Do not change shell profiles, user settings, keychains or global Git
  configuration. Do not use `sudo`, system package managers, launch agents, host credentials or the host
  Docker socket.
- Do not bypass sandbox restrictions.
- Bind test servers and the analysis service to loopback. Ports 21300–21399 are reserved for local test
  and service use. Limit build and test workers to two unless a benchmark explicitly needs more.
- Tests that need Docker or other host services must stay reproducible. Report them as unverified where
  those services are unavailable.
- Do not touch attached hardware, enrol services, flash firmware, install agents or change operating-system
  settings. Provide a manual checklist for such steps instead.
- Choose sensible defaults and record assumptions in the documentation.
- Do not push. Commit locally with conventional commit messages, and stage only the files a change touches.

## Before finishing a change

- Stop any servers, watchers or background jobs you started.
- Remove scratch outputs, logs, backups and caches you created. Keep deliverables and the user's changes.
- Update the documentation the change affects, and state what was verified and what was not.
- Commit the change, then summarise: what changed, the checks that ran, the remaining limitations and the
  commit hash.

## Language and tooling

- Python 3.12+, managed with `uv`. Dependencies are declared in `pyproject.toml` and pinned in `uv.lock`,
  which is committed. After changing `pyproject.toml`, run `uv lock` and commit the result. `uv lock --check`
  confirms that the lock matches.
- Source lives in `src/microflow/`; tests in `tests/`; examples in `examples/`; documentation in `docs/`.
  The CLI and HTTP references in `docs/reference/` are generated by `scripts/generate_reference.py`.
  Regenerate them after changing a command or a route.
- Verification commands (run from the repository root):
  - `uv sync --locked`
  - `uv run ruff check .` and `uv run ruff format --check .`
  - `uv run mypy`
  - `uv run pytest`
  - `python3 scripts/generate_reference.py --check`
  - `uv run python scripts/generate_license_inventory.py --check`
  - `uv run microflow make-sample-data --out-dir data/synthetic`
  - `uv run python examples/demo/run_demo.py --clean` (the end-to-end demonstration)
- Optional extras: `uv sync --locked --extra ml` (PyTorch) and `uv sync --locked --extra service` (FastAPI).
  Tests that need an extra skip without it.

## Engineering rules for this project

- **Deterministic tests:** every random step takes an explicit seed. Tests must not depend on wall-clock
  time, the network, or the order of unseeded sources.
- **Scientific units:** every quantitative value carries a unit. Calibration requires an explicit length
  unit (`microflow.units.Calibration`). Never silently assume pixels or micrometres.
- **Isolated dependencies:** install only through `uv`, into `.venv/` inside this repository. Do not install
  packages globally or into the system Python.
- **Clean temporary files:** tests write only under pytest's `tmp_path`. Generated data goes to git-ignored
  directories (`data/`, `benchmarks/out/`) and is removed when no longer needed.
- **Scope:** every analysis stage (preprocessing, segmentation, quantification, statistics, machine learning
  and the service) is implemented. A change to scientific behaviour needs a test against a known expected
  value and a note in `docs/audit.md`. Known gaps are tracked in `ROADMAP.md`.
- **Verification status:** do not describe code as verified unless it was executed. `ROADMAP.md` separates
  implemented, verified and unverified work.
